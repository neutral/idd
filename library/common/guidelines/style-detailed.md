# Style Guidelines (Detailed)

## Writing

- Use short paragraphs with clear transitions.
- Explain the rationale for non-trivial changes.
- Include an example when introducing a new contract or behavior.

## Naming

- Use kebab-case for new files and folders.
- Prefer full words over abbreviations.
- Add a domain qualifier when names are ambiguous.

## Code

- Follow the repo's existing formatting and lint rules.
- Document error behavior and recovery paths.
- Update `.desc.md` files with intent and blueprint links.
