# Style Guidelines (Balanced)

## Writing

- Use short, direct sentences.
- Prefer active voice.
- Keep headings in Title Case.

## Naming

- Use kebab-case for new files and folders.
- Prefix blueprint files with their type where helpful (contract, schema, glossary).
- Use descriptive names without numeric IDs.

## Code

- Follow the repo's existing formatting and lint rules.
- Add description files next to new source files using `.desc.md`.
- Keep changes scoped to the current intent and blueprint contract.
