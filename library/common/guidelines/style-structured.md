# Style Guidelines (Structured)

## Writing

- Use consistent sections in docs: Purpose, Inputs, Outputs, Checks.
- Use numbered steps for workflows.
- Keep headings in Title Case.

## Naming

- Use kebab-case for new files and folders.
- Prefix artifacts with their type when helpful (feature, behavior, contract).
- Avoid generic names like "misc" or "update".

## Code

- Keep modules aligned to a single responsibility.
- Use constants instead of magic values.
- Add `.desc.md` files next to new source files.
